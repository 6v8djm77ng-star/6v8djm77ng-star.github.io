# מערכת ספירת מלאי – מחסני המעבדה (15, 151)

מערכת WEB לספירת מלאי בטאבלטים, מעל מסמך ספירת המלאי של SAP Business One. מבוססת על אפיון גרסה 2 (26.11.2026).

### סטייה מכוונת מהאפיון
באפיון (13.4) כתוב שהכמות נכתבת למסמך ב-SAP אחרי כל פעולה. בפועל **המסמך נוצר פעם אחת, אחרי סגירת הסבב ואישור המנהל**. הסיבות:
- תקלה ב-SAP או ב-Service Layer לא עוצרת את הספירה במחסן.
- אין מסמך פתוח ב-SAP שמשתנה כל הזמן תוך כדי בקרה.
- כתיבה אחת לבדיקה ולגיבוי במקום אלפי כתיבות.

## ארכיטקטורה

```
טאבלט / מחשב (דפדפן)
      │  HTTPS / HTTP ברשת הפנימית
      ▼
server (Node.js, Fastify)  ──►  SQLite  (יומן פעולות, סבבים, משתמשים)  + גיבוי יומי
      │
      ├── SQL Server של SAP  – קריאה בלבד (צילום מצב, בדיקת הקפאה)
      └── Service Layer       – כתיבה אחת: מסמך ספירת מלאי
```

- `server/` – API, לוגיקה עסקית, חיבור ל-SAP. TypeScript.
- `web/` – React + MUI, עברית מימין לשמאל, מותאם לטאבלט, טלפון ומחשב.
- `server/src/sap/` – ממשק אחד, שני מימושים: `mock` (הדגמה ובדיקות) ו-`live` (SAP אמיתי).

## הרצה מקומית (מצב הדגמה, בלי SAP)

נדרש Node.js 20 ומעלה (מומלץ 22 LTS).

```bash
npm install
npm run build
```

```bash
cd server
cp .env.example .env
```

ב-`.env`: להגדיר `BOOTSTRAP_ADMIN_PIN` (4–8 ספרות) ולהשאיר `SAP_MODE=mock`.

```bash
npm start
```

לפתוח `http://localhost:8080` ולהיכנס עם `admin` והקוד שהוגדר.

בדיקות (תרחישי הקבלה א'–ח' מסעיף 17 באפיון ועוד):

```bash
npm test
```

## התקנה בחברה (שרת Windows ברשת)

### 1. הרשאות SAP – לביצוע ע״י IT
המערכת צריכה שני משתמשים ייעודיים. **אלה שינויי הרשאות ב-SQL Server וב-SAP, ולכן הם לביצוע של איש IT מורשה, לא אוטומטית:**

1. **SQL Server, קריאה בלבד:** login עם תפקיד `db_datareader` על מסד החברה (`SAP_OIG`) בלבד. המערכת קוראת רק מהטבלאות `OITM`, `OITW`, `OBCD`, `OINM`.
2. **משתמש SAP ל-Service Layer:** הרשאה ליצירת מסמך ספירת מלאי (Inventory Counting) בלבד, **בלי** הרשאה ל-Inventory Posting.

### 2. התקנה
- על שרת שרואה את SQL Server של SAP ואת ה-Service Layer, לדוגמה שרת ה-SAP עצמו.
- להתקין Node.js 22 LTS.
- להעתיק את התיקייה ולהריץ `npm install` ו-`npm run build`.
- ב-`server/.env`: למלא את הפרטים לפי `.env.example` ולהגדיר `SAP_MODE=live`.

### 3. הרצה כשירות Windows (עם NSSM)
```bash
nssm install InventoryCount "C:\Program Files\nodejs\node.exe" "C:\apps\inventory-count\server\dist\index.js"
```
```bash
nssm set InventoryCount AppDirectory "C:\apps\inventory-count\server"
```
```bash
nssm start InventoryCount
```

### 4. בדיקה לפני ספירה אמיתית
1. לפתוח סבב ניסיון על מחסן אחד ולוודא שמספר הפריטים והיתרות תואמים לדוח מלאי ב-SAP.
2. לספור 3–4 פריטים מכמה טאבלטים, לעבור לבקרה ולסגור.
3. לשלוח ל-SAP ולוודא שנוצר מסמך ספירת מלאי עם השורות הנכונות. **לא לבצע ממנו התאמת מלאי.** אחרי הבדיקה, לסגור או לבטל את המסמך ב-SAP.

### HTTPS
ברשת פנימית אפשר לעבוד ב-HTTP. מומלץ HTTPS (reverse proxy כמו IIS או Caddy) ואז `COOKIE_SECURE=true`.

## גיבוי ושחזור
- גיבוי אוטומטי בהפעלה ופעם ביום אל `data/backups/`. נשמרים 14 העותקים האחרונים.
- **שחזור:** לעצור את השירות, להעתיק את קובץ הגיבוי במקום `data/inventory.db`, ולהפעיל מחדש.
- מומלץ לכלול את `data/backups/` בגיבוי הרגיל של השרת.

## שלב ב' (לא כלול)
עבודה Offline עם סנכרון, תפקידי בודק ומנהל מערכת, מחסנים נוספים.

**נוסף מתוך שלב ב':** צילום פריט חריג (נדחס במכשיר ל-~200KB, נשמר במסד הנתונים ולכן נכלל בגיבוי), ייצוא PDF לכל הדוחות.
